# 核心概念速查

按「真正影响你怎么用」排序，先记这些。

## 1. Goal（目标）

你希望最终世界变成什么样。  
好目标可验收：「在库里生成学习地图」比「帮我学 agent」清楚。

## 2. Tool / Action（工具 / 动作）

模型本身不能直接改你电脑；要通过工具：读文件、写文件、搜索、浏览器等。  
**工具边界 = agent 能力边界。**

## 3. Observation（观察 / 反馈）

工具返回的结果：成功、报错、搜到的内容。  
Agent 靠这些决定下一步，而不是空想。

## 4. Plan / Loop（计划 / 循环）

常见循环：

`思考 → 选工具 → 执行 → 观察 → 再思考 … → 交付`

有的系统显式写计划，有的边做边想。对初学者：知道「它在循环」比背框架名重要。

## 5. Memory（记忆）

- **对话上下文**：这次聊天里说过的话  
- **长期记忆**：跨会话记住你的偏好、路径  
- **外部记忆**：Obsidian、Notion、文件本身  

你的 Obsidian 库，本质上就是很好的外部记忆。

## 6. Context（上下文窗口）

一次能「看见」的信息量有限。  
所以 agent 常要：摘要、检索、只读相关文件，而不是把整个库塞进去。

## 7. Autonomy（自主程度）

从低到高大概是：

1. 每步都问你  
2. 小步自己做，关键步确认  
3. 大部分自己做，结束汇报  
4. 定时/事件触发，你不在也跑  

自主越高越省事，也越需要边界（别乱删、别乱发）。

## 8. Guardrails（护栏）

权限、审批、禁止事项、只能读不能写等。  
学 agent 时同步学「什么不该自动做」。

## 9. Evaluation（验收）

怎么知道做完了？有文件、有清单、测试通过、你点头。  
没有验收标准的目标，agent 很容易「说完了但事没办完」。

## 10. Multi-agent（多智能体）

多个角色分工：调研的、写的、审查的。  
你侧边栏里那些不同 bot，就是这个思路的产品形态。先把单 agent 吃透，再玩多 agent。
