# Agent 和聊天机器人有什么不同

用同一张对照表建立直觉：

| 维度 | 聊天机器人 | Agent |
|------|------------|-------|
| 交互形态 | 你问一句，它答一句 | 你给目标，它可能连续做很多步 |
| 状态 | 主要靠对话上下文 | 常有任务状态、待办、记忆、外部文件 |
| 行动 | 多半只生成文字 | 会调用工具：读盘、检索、写入、调用 API |
| 失败处理 | 「我不知道」就停 | 换工具、重试、追问你、缩小范围 |
| 成功标准 | 回答是否合理 | 事情是否办完（文件在不在、列表齐不齐） |

## 灰色地带（真实产品里很常见）

很多产品两边都沾：

- 带「搜索网页再回答」的聊天 → 有一点 agent 味，但仍偏问答。
- 带「帮我改仓库 / 订票 / 整理库」的助手 → 更接近 agent。
- 定时 routine、事件监听 → agent 在你不在线时也会动。

不必纠结标签。问自己一句就行：

> 它是在**帮我把事做完**，还是只在**跟我说话**？

## 对你学习的启示

学 agent，不要只收集「酷定义」。  
更好的方法是：每次用 Grok Bot 完成一件事后，写三行：

1. 我给的目标是什么？
2. 它用了哪些工具 / 步骤？
3. 哪一步如果没有工具，就做不成？
