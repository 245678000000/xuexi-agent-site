# 一次 Agent 任务长什么样

用一个你正在做的真实例子拆解。

## 例子：你说「我想学 agent，帮我在 Obsidian 建学习路径」

理想运转大致是：

1. **理解目标**  
   不是只要一段话，而是要「可学习的库结构 + 笔记」。
2. **检查已有条件**  
   电脑在线吗？库路径在哪？有没有现成连接器？
3. **选行动**  
   在桌面库创建文件夹、写 Markdown、必要时登记进 Obsidian。
4. **执行工具**  
   真正创建文件（改变外部世界）。
5. **观察结果**  
   文件在不在、内容是否可读。
6. **交付**  
   告诉你路径、怎么打开、下一步可做什么。

## 你可以在每次使用后填的模板

复制到 `日记/`：

```markdown
## 任务
-

## 我给的目标清楚吗？
- 清楚 / 模糊 → 下次可改成：

## 它大概走了哪些步
1.
2.
3.

## 用到了什么「手」（工具）
-

## 哪里像 agent，哪里只是聊天
-

## 我学到的一个概念
-
```

## 关键洞察

Agent 的质量，往往不取决于「模型嘴有多甜」，而取决于：

- 目标是否可验收  
- 工具是否够用、权限是否对  
- 反馈是否被认真用（出错会不会改策略）  
- 最后有没有把结果落到文件/系统里
