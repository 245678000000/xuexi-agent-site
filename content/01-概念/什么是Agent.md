# 什么是 Agent

## 直观理解

把「大模型」想成一个很会说、很会推理的大脑。  
**Agent** 是在这颗大脑外面，再加三样东西：

1. **目标**：不是只回答一句，而是要完成一件事（例如：整理笔记、查资料、改文件）。
2. **工具**：能做事的手——读文件、搜网页、写 Obsidian、发邮件等。
3. **循环**：看现状 → 想下一步 → 用工具 → 看结果 → 再决定，直到完成或承认做不到。

没有工具、也不会多步推进的，多半只是「聊天」；有目标、会用工具、会根据反馈改计划的，才更像 agent。

## 一个生活类比

你请助理：「帮我准备下周面试材料。」

- 纯聊天：给你一段建议文字，结束。
- Agent：去文件夹找简历 → 搜岗位 JD → 对照缺口列提纲 → 写成笔记放进库里 → 问你缺的信息 → 再改一版。

中间每一步都可能失败或偏航，agent 的价值在于**能继续处理**，而不是一次答完。

## 和几个容易混的词

| 词 | 大概是什么 | 和 agent 的关系 |
|----|------------|-----------------|
| LLM / 大模型 | 文本推理引擎 | agent 的「脑」 |
| Chatbot | 对话界面 | 可以包一层 agent，但本身不等于 agent |
| Workflow / 流水线 | 预先写死的步骤 | 确定性高；agent 更灵活、也更不可控 |
| Tool / 插件 / Connector | 可调用的能力 | agent 的「手」 |
| RAG | 先检索再回答 | 常被 agent 用作一种工具策略 |

## 你先需要掌握的程度

现阶段不必背论文定义。能用自己的话说明下面三点就够：

1. Agent 有**目标**，不只是接话。
2. Agent 会**用工具**改变外部世界（或至少读取外部信息）。
3. Agent 会**根据结果调整下一步**。
